# Этап 0: установка и первый запуск

Всё делается на **домашнем ПК** (Ryzen 9, RTX 2080 Ti). Рабочий ПК для редактора слишком слабый.

Займёт 2–4 часа, в основном это скачивание и первая компиляция шейдеров. После каждого шага есть проверка. Если что-то не совпадает, остановитесь и пришлите мне скриншот или текст ошибки.

## Шаг 1. Подготовить компьютер

1. **Память.** Пока не докупили 32 ГБ, увеличьте файл подкачки: Пуск → «Настройка представления и производительности системы» → Дополнительно → Виртуальная память → Изменить. Уберите галочку «Автоматически», выберите SSD и задайте размер 32768 МБ (исходный и максимальный). Перезагрузите компьютер.
2. **Диск.** Нужно 150–200 ГБ свободного места на SSD: сам движок весит около 60 ГБ, проект и кэш шейдеров займут остальное.
3. **Драйвер видеокарты.** Поставьте свежий драйвер NVIDIA Game Ready.

Проверка: в Диспетчере задач (вкладка «Производительность») видны процессор Ryzen 9 и видеокарта RTX 2080 Ti. Запишите точную модель процессора, она нужна для покупки памяти.

## Шаг 2. Установить Unreal Engine 5

1. Скачайте **Epic Games Launcher** с сайта unrealengine.com, установите и войдите в аккаунт Epic. Если аккаунта нет, создайте.
2. В лаунчере откройте **Unreal Engine → Библиотека**, нажмите **+** рядом с «Версии движка» и выберите **самую новую версию 5.x** (не Preview).
3. Перед установкой нажмите **Параметры** и оставьте:
   - Core Components: да;
   - Starter Content: да;
   - Templates and Feature Packs: **обязательно да**;
   - Engine Source: да;
   - Editor symbols for debugging: **нет** (это десятки ГБ, понадобятся позже);
   - платформы Android, iOS, Linux: нет.
4. Установите движок на SSD.

Проверка: движок запускается из лаунчера кнопкой «Запустить». **Напишите мне номер версии** (например, 5.x.y). Код я пишу под неё.

## Шаг 3. Установить Visual Studio (для C++)

1. Скачайте **Visual Studio Community** (бесплатная). Версию берите ту, которую Epic рекомендует для вашей версии движка: в документации Unreal есть страница «Setting Up Visual Studio for Unreal Engine».
2. В установщике отметьте наборы:
   - **Разработка классических приложений на C++**;
   - **Разработка игр на C++**, а в нём справа галочку **Unreal Engine installer** или **Unreal Engine integration**, если есть;
   - **Разработка классических приложений .NET**.
3. Во вкладке «Отдельные компоненты» проверьте, что стоит **Windows 10 SDK или Windows 11 SDK** (последний из списка).

Проверка: Visual Studio открывается.

## Шаг 4. Git и проект

1. Установите **Git for Windows** (git-scm.com). Git LFS в нём уже есть.
2. Установите **GitHub Desktop** (desktop.github.com) и войдите в свой аккаунт GitHub. Через него проще забирать мои изменения.
3. Откройте «Командную строку» и выполните по очереди:
   ```
   git lfs install
   git config --global core.longpaths true
   ```
4. В GitHub Desktop: File → Clone repository → `seezmate1-dot/1`. Путь возьмите **короткий**, например `C:\Dev\ash`. У Unreal бывают проблемы с длинными путями.
5. Переключитесь на ветку `claude/python-game-review-18tnfb` (кнопка Current branch вверху).

Проверка: в папке `C:\Dev\ash\AshRPG` лежит файл `AshRPG.uproject`.

## Шаг 5. Собрать проект

1. Правый клик по `AshRPG.uproject` → **Switch Unreal Engine version** (или «Показать дополнительные параметры» → Switch Unreal Engine version). Выберите установленную версию и нажмите OK.
2. Двойной клик по `AshRPG.uproject`. Появится окно «The following modules are missing or built with a different engine version... Would you like to rebuild them now?» Нажмите **Yes**.
3. Ждите. Сборка C++ займёт 1–5 минут, потом редактор откроется и начнёт компилировать шейдеры (счётчик внизу справа). В первый раз это может идти 20–60 минут.

Если вместо редактора появилось «could not be compiled. Try rebuilding from source manually»:
1. В папке `AshRPG` появится файл `AshRPG.sln`. Если его нет: правый клик по `AshRPG.uproject` → **Generate Visual Studio project files**.
2. Откройте `AshRPG.sln` в Visual Studio, вверху выберите **Development Editor** и **Win64**, затем меню Сборка → Собрать решение.
3. Пришлите мне окно «Вывод» или «Список ошибок» целиком (текстом или скриншотами).

Проверка: редактор открыт, внизу справа нет счётчика шейдеров.

## Шаг 6. Контент Third Person и наш герой

1. В редакторе внизу откройте **Content Drawer** (Ctrl+Пробел).
2. Нажмите **+ Add** → **Add Feature or Content Pack**.
3. Вкладка **Blueprint** → **Third Person** → **Add to Project**. Из этого пака нам нужны только манекен, анимации и тестовая карта. Персонаж у нас свой, на C++.
4. Откройте карту из папки `ThirdPerson` (в папке `Maps` или прямо в `ThirdPerson`): двойной клик по ней.
5. Меню **Edit → Project Settings → Maps & Modes**:
   - **Default GameMode** не трогайте: там уже стоит `AshGameMode`. **Не** выбирайте `BP_ThirdPersonGameMode` из пака;
   - **Editor Startup Map** и **Game Default Map**: выберите открытую карту.
6. **Tools → Execute Python Script** → `C:\Dev\ash\AshRPG\Content\Python\ash_setup_hero.py`. Скрипт сам найдёт манекена и его анимации, подключит их к нашему герою и уберёт с карты чужой режим игры. В Output Log должно появиться `Stage 1 setup done`.

Проверка: нажмите **Play** (Alt+P) и попробуйте управление:

| Действие | Клавиатура и мышь | Геймпад |
|---|---|---|
| Ходьба | W A S D | левый стик |
| Камера | мышь | правый стик |
| Спринт (держать) | Shift | нажатие левого стика |
| Перекат | Пробел | B (Xbox) / ◯ (PlayStation) |
| Прыжок | F | A (Xbox) / ✕ (PlayStation) |

Что должно быть:
- манекен бегает, камера плавно следует за ним и не проходит сквозь стены;
- перекат делает рывок примерно на 4 м и тратит выносливость, спринт тоже её тратит;
- выносливость восстанавливается через секунду после траты.

Выносливость видно так: нажмите тильду и введите `showdebug abilitysystem`. В углу появится список атрибутов (Health, Stamina и другие).

Если вместо манекена летает серый шар или герой невидимый, пришлите мне Output Log. Если камера по вертикали работает наоборот, тоже напишите: это одна строчка в коде.

## Шаг 7. Проверка этапа 0

1. Меню **Tools → Execute Python Script**, выберите файл `C:\Dev\ash\AshRPG\Content\Python\ash_stage0_check.py`.
2. Внизу откройте **Output Log** (меню Window → Output Log). Там появится отчёт, который начинается со строки `=== AshRPG stage 0 report ===`. Тот же отчёт сохранится в `AshRPG\Saved\AshStage0Report.txt`.
3. Аудит ассетов (раздел 53.5): **Tools → Execute Python Script** → `ash_perf_audit.py` из той же папки. Скрипт ничего не меняет, только составляет список. Отчёт появится в Output Log и в `AshRPG\Saved\AshPerfAudit.txt`. На этапе 0 там будет почти пусто: проверка понадобится, когда пойдут паки из Fab.
4. Замер в отдельном окне: стрелка рядом с кнопкой Play → **Standalone Game**. В игре нажмите тильду, введите `stat unit`, сделайте скриншот. Потом введите `stat gpu` и сделайте ещё один.

**Пришлите мне:**
- номер версии движка;
- работает ли управление из шага 6 (что не так, если не так);
- текст отчёта из `AshStage0Report.txt`;
- два скриншота: со `stat unit` и со `stat gpu` (из Standalone, не из окна редактора).

## Шаг 8. Сохранить в GitHub

1. В редакторе: File → Save All.
2. Закройте редактор и откройте GitHub Desktop. Слева будут изменения: новые файлы в `Content/ThirdPerson`, `Content/Characters` и др. Папок `Binaries`, `Intermediate`, `Saved` там быть **не должно**: они исключены.
3. Внизу напишите Summary: `Этап 0: контент Third Person`, затем нажмите **Commit**, потом **Push origin**.

Готово, когда (раздел 12): проект собирается, Git настроен, настройки Lumen, Nanite и теней применены, отчёт проверки без FAIL и MISSING, а герой бегает, делает перекат и прыгает (этап 1).

## Правила на будущее

- **Сторонние паки** из Fab и Megascans импортируйте в `Content/ThirdParty/`. В Git они не попадают (иначе быстро кончится бесплатное место Git LFS), а каждый пак записывается строкой в `docs/ASSETS.csv` с источником и лицензией (раздел 4).
- **Перед работой** в GitHub Desktop нажмите **Fetch origin / Pull**, чтобы забрать мой новый код. После этого правый клик по `AshRPG.uproject` → Generate Visual Studio project files и снова двойной клик по `.uproject` (ответить Yes на пересборку).
- **Движок в середине проекта не обновляем** (раздел 3).
- **Перед коммитом с новыми ассетами** запускайте `ash_perf_audit.py` и исправляйте то, что он нашёл. Как исправить без потери качества, написано прямо в отчёте.
- **Производительность меряем** только в Standalone Game или в упакованной сборке, окно редактора искажает цифры. Результаты записываются в `docs/PERF_LOG.md`.
